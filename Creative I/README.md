# Умный подбор подрядчиков (#79-lite)

## 1. Название и задача

Сервис помогает заказчику мероприятия в Казахстане выбрать подходящего подрядчика из уже найденного каталога своего города. Ценность решения — в проверяемом объяснении каждой рекомендации, а не в простом выводе списка.

## 2. Что реализовано

- фильтрация по городу, категории, дате, бюджету, формату, длительности и языку;
- поддержка составных значений через `|` в `categories`, `event_formats` и `busy_dates`;
- три различимых исхода: `matched`, `no_category`, `no_match`;
- до трёх карточек с детерминированным порядком;
- численные причины отказа для пустой выдачи;
- онлайн-объяснение через OpenAI и офлайн-fallback без ключа или сети;
- кеширование только успешных API-объяснений по SHA-256 запроса и кандидата.

## 3. Как работает решение

`Request` содержит обязательные поля `city`, `date`, `event_format`, `category`, `budget_kzt` и опциональные `duration_hours`, `language`. Сначала `hard_filter()` отбрасывает неподходящих подрядчиков и собирает причины отказа. Затем `rank()` считает числовой score и сортирует по `score desc, price_from_kzt asc, id asc`. Для уже выбранных кандидатов `explain()` формирует 1–2 фактических предложения.

`price_from_kzt` трактуется как стартовая цена «от», а не как гарантированная итоговая стоимость. Пустой `max_hours` не считается ограничением по длительности.

## 4. Технологии

- Python 3.13 (проверено локально);
- стандартная библиотека Python: `csv`, `dataclasses`, `hashlib`, `json`, `re`;
- `pytest` для тестов;
- OpenAI Python SDK и модель `gpt-4o-mini` для необязательного объяснения через Responses API;
- JSON-файлы в `.cache/explanations` для кеша успешных API-ответов.

## 5. Архитектура

- `src/contractor_matcher.py` — модели данных, CSV-загрузка, жёсткий фильтр, стабильное ранжирование, объяснения и fallback.
- `tests/test_matcher.py` — проверки составных категорий/форматов, трёх исходов, лимита карточек, смены даты и отказа API.

LLM не фильтрует и не выбирает кандидатов. При отсутствии `OPENAI_API_KEY`, ошибке сети, SDK или JSON используется локальный текстовый fallback. Локальный score сейчас является стабильным лексическим прокси; обучение модели не используется.

## 6. Установка и запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 -m pytest -q
```

Загрузка каталога:

```python
from src.contractor_matcher import Request, load_catalog, match

request = Request(
    city="Алматы", date="2026-10-10", event_format="корпоратив",
    category="Ведущий", budget_kzt=900000,
    duration_hours=6, language="английский",
)
result = match(request, load_catalog("data/contractors.csv"))
print(result.status, result.message, result.matches)
```

Для онлайн-объяснений задайте `OPENAI_API_KEY`. Без ключа сервис работает локально.

## 7. Как проверить решение

После установки зависимостей повторяемый набор проверок запускается командой:

```bash
python3 -m pytest -q
```

Тесты отдельно проверяют плотную выдачу с ограничением в три карточки, составной `event_formats`, отсутствие категории, отсутствие подходящих кандидатов, разные даты с занятым подрядчиком и fallback при сетевой ошибке OpenAI.

Реальный вывод трёх обязательных сценариев будет добавлен после получения файла `hackathon-dataset-anonymized.csv`. На момент подготовки этого репозитория файла нет, поэтому реальные числа и результаты намеренно не выдумываются.

## 8. Данные и интеграции

Ожидается CSV из материалов хакатона `hackathon-dataset-anonymized.csv`. Его нужно положить в `data/contractors.csv`; обязательные поля: `id, anon_name, categories, city, city_imputed, synthetic, price_from_kzt, price_imputed, event_formats, languages, max_hours, busy_dates, description`.

Поля `synthetic`, `city_imputed` и `price_imputed` сохраняются при загрузке и доступны в карточке. API OpenAI опционален: при недоступном ключе или сети применяется fallback.

## 9. Ограничения

- В текущем репозитории нет исходного CSV, UI, бронирования, заявок и уведомлений.
- Deployed-версии нет; предусмотрен локальный запуск.
- Реальные эмбеддинги пока не подключены: ранжирование использует стабильный локальный лексический прокси. При подключении готовых embeddings нужно сохранить текущий жёсткий фильтр и ключи сортировки.

## 10. Воспроизводимость и честность результата

Одинаковый запрос сортируется одинаково благодаря последнему tie-break по `id`. Занятая дата исключается до ранжирования, поэтому смена даты меняет состав только по данным `busy_dates`, а не случайно. В объяснениях цена называется стартовой, а отсутствие результатов сопровождается численными причинами.
